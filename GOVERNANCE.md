# Governance

L-Desk is maintained by its project owner with a lightweight maintainer-led
model. The maintainer sets release scope, reviews safety/security impact, and
has final responsibility for merges and releases.

Decisions favor:

1. physical and firmware safety;
2. deterministic, testable behavior;
3. maintainability and clear ownership boundaries;
4. minimal hardware and software complexity;
5. compatibility with the documented reference build.

Substantial changes should begin with an issue. Consensus is preferred, but the
maintainer may reject technically valid work that expands scope, weakens a
safety invariant, lacks hardware evidence, or creates an unsustainable
maintenance burden.

No release is promised on a fixed schedule. A tag requires passing automated
quality gates and the physical commissioning evidence defined by the project.
